L'objectif de la tache est de décoreller la liste des plateformes en base de données des imports utilisateurs.
Désormais la liste des plateforme est fournie directement par l'application.

L'objectif de la tache est de modifier le schéma de base de données pour la table t_platform.
Cette  table doit désormais contenir les colonnes : 
| Column | Type | Null | Description |
| --- | --- | --- | --- |
| `id` | `BIGINT` | No | Technical identifier generated by `s_platform`. |
| `name` | `VARCHAR(64)` | No | Platform name. |
| `release_date` | `TIMESTAMP` | No | Platform release date. |
| `end_date` | `TIMESTAMP` | Yes | Platform release date. |
| `manufacturer` | `VARCHAR(128)` | No | Platform manufacturer. |
| `description` | `JSONB` | Yes | Structured platform description. |

De plus, cette table doit être rempli si ce n'est pas le cas au démarrage via un script de migration de la base de donnée dédiée avec le contenue du fichier csv fourni. Si la date est "Inconnue" dans le csv alors on met la colonne a NULL en base de donnée.

On considère  que la base de donnée est vide au démarrage, si ce n'est pas le cas, le script de migration vide la base de donnée et plus précisément les table en rapport avec plateforme a savoir : t_game, t_platform.

Ensuite la fonction d'import des utilisateurs ne créé plus de plateforme mais ce sert de la liste des plateformes existantes pour retrouver la plateforme associé au jeu a importer en fonction de la plateforme fournie par l'utilisateur dans son fichier de collection.
Il faut pouvoir retrouver des plateformes meme si il y a une coquille dans le nom de la plateforme fournie par l'utilisateur ou si il y a une différence de casse, d'espaces ou d'accents. tu calcul un seuil de correspondance lors de l'import, si le seuil est trop faible alors tu fait une liste des jeux impactés et tu le rajoute au warning de retour de l'import et tu envoi un mail a l'administrateur du projet (adresse mail configuré en .env) pour lui indiquer de faire la vérification manuelle necessaire avec la liste des jeux impactés. Si le seuil vraiement trop faible, alors on n'importe pas le jeu et on le rajoute dans les warnings du context d'import.
Les seuils sont : 
 - 100% match parfait
 - < 75% match avec warning et vérificatio nmanuelle
 - < 25% pas d'import
 - 0% match innexistant
 Ces valeurs son les seuils par défaut mais ils doivent pouvoir être configurés par variable d'env dans le fichier .env avec MATCHING_LOW_LVL_RATING et MATCHING_HIGH_LEVEL_RATING.

Il faut donc modifier le frontend et l'écran listant les plateformes pour prendre en compte les nouvelles colonnes et celles qui n'existent plus.

Le rendu mobile de la page plateforme doit etre réalisé comme celui des jeux en affichant dans chaque encart de plateforme : 
 - Nom, Sur la premiere ligne
 - Release date / end_date sur la deuxième ligne.

Il faut modifier le résultat de l'import pour indiquer le nombre de plateforme liés à l'import et non plus le nombre de plateformes ajouté au référentiel commun. Coté frontend, il faut reflété ce changement dans les encarts de resumé de l'import affiché.

Il faut modifier le endpoint de recherche des plateformes coté backend pour retourner le bon format des plateformes.
